# 🚀 Step 6: Application Load Balancer & Auto Scaling Compute Fleet

> **File:** `compute-alb.tf`  
> **Architecture Level:** Tier 6 — Stateless Compute & High-Availability Traffic Ingress  
> **Key Deliverable:** Public Web URL (`wordpress_url`) for live browser access

---

## 🧠 Why Application Load Balancers & Auto Scaling?

In Phase 1, we started with a single monolithic `t3.micro` EC2 instance attached directly to a static Elastic IP:
* If that single server halted or had high traffic, the entire website went down.
* All components (Nginx, PHP, MySQL, media files) fought for 1 GB RAM.

In Step 6, we implement the **True Cloud-Native Architecture**:
1. **Application Load Balancer (ALB):** Spans across 2 Public Subnets in 2 Availability Zones (`ap-south-1a` & `ap-south-1b`).
2. **Stateless EC2 Fleet:** Multiple Ubuntu 24.04 servers managed by an **Auto Scaling Group (ASG)**.
3. **Automated RDS Binding:** Upon booting, instances automatically configure `/var/www/html/wp-config.php` with our Step 4 RDS MySQL database endpoint.
4. **Self-Healing:** If an instance crashes or fails health checks on `/health.html`, the ALB stops routing to it and the ASG terminates and replaces it automatically within minutes.

```text
             │
             ▼ Port 3306 (MySQL)

   (wp-lab-db.c5ygss4s6buv.ap-south-1.rds.amazonaws.com)
```

## 🔍 Key Architectural Primitives

### 1. `data "aws_ami" "ubuntu"` (Dynamic AMI Resolution)
Hardcoding AMI IDs (e.g. `ami-053b12d3152c0cc74`) is an anti-pattern because AWS constantly depreciates and rotates AMIs. This data source dynamically queries the AWS API for Canonical's latest official Ubuntu 24.04 Noble LTS AMI in the active region.

### 2. Dedicated ALB Health Check (`/health.html`)
WordPress initialization and database migrations can sometimes take 30–60 seconds. If an ALB checks `/` while WordPress is still loading, it might receive a temporary 500 error and prematurely kill the instance.
By serving an ultra-lightweight `/health.html` from Nginx:
* The ALB verifies that Nginx and the network stack are alive.
* Health checks succeed reliably in < 5 milliseconds.

### 3. Launch Template (`aws_launch_template.web`)
Provides the immutable recipe for all EC2 instances:
* Injects our `install.sh` bootstrap script with the RDS database address.
* Binds the IAM Instance Profile (enabling browser SSM Session Manager terminals without Port 22 SSH).
* Attaches `wp-lab-web-sg` (ensuring instances reject all direct internet traffic and accept requests solely from the ALB).
